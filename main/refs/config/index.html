    Config

    invoke_tasklib.config ¶

    Config resolution for invoke-tasklib tasks.

    Consuming projects set project-specific values under a tasklib key in their invoke.yaml, e.g.::

    tasklib:
  package:
    name: coola
  paths:
    docs_config: docs/mkdocs.yml

    Only package.name (the distribution name) is required; everything else has a default derived from it. package.import_name defaults to the name with - replaced by _.

    FIX_STEPS: tuple[str, ...] = (
    "lint",
    "format-python",
    "format-docstrings",
    "shell",
)

    The steps that fix.all can run (tasklib.fix.tasks).

    They are listed in the order that converges: the lint fixes come before the formatting, which has the last word on the layout.

    invoke_tasklib.config.Unset ¶

    Bases: str

    The placeholder of a boolean or an integer that no source sets.

    It is registered as the default of such a key, instead of None, so a null that a user writes in invoke.yaml can be told from "not set". It is a str, so Invoke does not cast the text of an environment variable to the type of the default: the text is kept and parsed by the validation.

    Example usage:

    >>> from invoke_tasklib.config._schema import Unset
>>> isinstance(Unset(), str)
True

    invoke_tasklib.config.default_config ¶

    default_config() -> dict[str, dict[str, object]]

    Return the defaults of the tasklib config section.

    The defaults are registered with Invoke (see make_ns) so that the keys can also be set with the INVOKE_TASKLIB_<SECTION>_<KEY> environment variables, for example INVOKE_TASKLIB_PATHS_SRC. Invoke only reads an environment variable for a key that exists in the defaults. Invoke casts the variable to the type of the default, and it reads any text but 0 as true for a boolean, so the booleans and the integers are registered with an Unset: the text is kept and parsed by the validation. The real defaults stay in SCHEMA.

    Returns:

    Type Description
    dict[str, dict[str, object]]

    A new dict with the package, paths, groups,
    dict[str, dict[str, object]]

    test, check and fix sections, each a copy of its
    dict[str, dict[str, object]]

    DEFAULT_* dict, except that a boolean or an integer is
    dict[str, dict[str, object]]

    an Unset.

    Example usage:

    >>> from invoke_tasklib.config import default_config
>>> sorted(default_config())
['check', 'fix', 'groups', 'package', 'paths', 'test']
>>> default_config()["groups"]
{'install': 'dev', 'update': 'dev,docs'}
>>> default_config()["test"]["xdoctest"] == ""
True

    invoke_tasklib.config.get_config ¶

    get_config(c: Context) -> TasklibConfig

    Return the effective tasklib config, merging user overrides from invoke.yaml (under the tasklib key) on top of the defaults.

    Parameters:

    Name Type Description Default
    c Context

    The invoke context.

    		 required

    Returns:

    Type Description
    TasklibConfig

    A frozen dataclass with the resolved package, paths,
    TasklibConfig

    groups, test, check and fix sections, each a
    TasklibConfig

    frozen dataclass too, e.g. cfg.paths.src.

    Raises:

    Type Description
    ValueError

    If the config is invalid: an unknown key, a missing tasklib.package.name or a value that is not valid. The message names the key. The rules of every key are listed in the user guide, see uguide/config.md.

    Example usage:

    >>> from invoke.config import Config
>>> from invoke.context import Context
>>> from invoke_tasklib.config import get_config
>>> overrides = {"tasklib": {"package": {"name": "mypkg"}}}
>>> c = Context(config=Config(overrides=overrides))
>>> cfg = get_config(c)
>>> cfg.package.import_name
'mypkg'
>>> cfg.paths.src
'src/mypkg'
>>> cfg.groups
GroupsConfig(install=('dev',), update=('dev', 'docs'))
>>> cfg.test.unit_timeout
10
>>> cfg.check.tasks[0]
'format-python'

    invoke_tasklib.config.json_schema ¶

    json_schema() -> dict[str, Any]

    Return the JSON schema of the tasklib config.

    The schema is generated from SCHEMA, so it cannot drift from the keys and the defaults. It lets an editor complete and check the invoke.yaml file. Other top-level keys (the config of Invoke itself) are allowed.

    Returns:

    Type Description
    dict[str, Any]

    The schema, as a dict that can be dumped as JSON.

    Example usage:

    >>> from invoke_tasklib.config import json_schema
>>> schema = json_schema()
>>> sorted(schema["properties"]["tasklib"]["properties"])
['check', 'fix', 'groups', 'package', 'paths', 'test']

    invoke_tasklib.config.load_config ¶

    load_config(c: Context) -> TasklibConfig

    Return the effective tasklib config, exiting cleanly on an invalid config.

    The tasks use this function instead of get_config so that an invalid config is reported as a one-line message and the exit code 2 rather than as a Python traceback. get_config is the function to use programmatically, because it raises a ValueError.

    Parameters:

    Name Type Description Default
    c Context

    The invoke context.

    		 required

    Returns:

    Type Description
    TasklibConfig

    The resolved config, see get_config.

    Raises:

    Type Description
    Exit

    If get_config raises a ValueError, or if Invoke runs from another directory than the one of tasks.py. The message is the one of the ValueError.

    Example usage:

    >>> from invoke.config import Config
>>> from invoke.context import Context
>>> from invoke_tasklib.config import load_config
>>> overrides = {"tasklib": {"package": {"name": "mypkg"}}}
>>> c = Context(config=Config(overrides=overrides))
>>> load_config(c).package.name
'mypkg'
